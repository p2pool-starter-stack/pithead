# Configuration-editor metadata parity

Go derives configuration-editor path classification, sparse-default paths,
version flags and the newest terminal dashboard apply. Python retains host and
reference document reads, merging, secret masking, core-key reads, audit reads
and explicit provider callbacks.

## Native boundary

The normal `read_config` path uses one `editor-metadata` request through the
existing ordered `wizard-config` protocol. The six public classification helpers
also have individual native operations. Their typed trees retain insertion
order, Unicode strings and scalar distinctions. Schema and host inputs are
projected to keys, structure and Boolean markers; raw scalar configuration
values never enter this metadata request. Audit rows send only action/status
selectors. The selected status and opaque identifier come from a shallow Python
snapshot, with a forced-interleaving test proving that a later live-row change
cannot alter the returned generation.

Leaf traversal excludes underscore keys at every depth and the root version
stamp, recognizes only the literal Boolean secret sentinel, and includes arrays
only when requested. Approval names come from the existing Python map, avoiding
another policy list. Classification retains sorted confirmation/approval paths,
the explicit-confirmation union and retired SSH exclusions. Default paths retain
schema order and the reference dotted-path lookup, including omitted arrays.
Mandatory null classification lists raise `TypeError`.

Version metadata preserves strict ASCII stamps and lenient running-version
parsing. It validates all three components before integer conversion, matches
locked Python 3.11 Unicode digit behavior and receives that interpreter's integer
conversion limit. A failed semantic conversion retains the standalone version
helper's original stamp-removal side effect. Arbitrary Python-only schema/key
types and lazy iterator side effects are outside the JSON service boundary.

Native replies must have the complete expected metadata shape, string path lists,
Boolean flags and a valid terminal audit index. Normal metadata is staged and
applied only after validation; helper failures cannot publish a partial result
or select the Python reference. The resulting configuration retains its original
dictionary identity, and opaque audit identifiers stay in Python.

The reference metadata assembly is extracted from `read_config` without changing
its providers or order. The three explicit compatibility paths share that
existing reference orchestration/getter/version logic: replaced providers retain
their call order and partial-update failure boundaries, replaced dotted getters
receive each path in order, and replaced version parsers remain observable.
These interpositions are counted separately; normal native failures do not use
them. Unset, Bash and Python selection retain the reference path.
